02

Qu'est-ce qu'un algorithme ?

Algorithme définition informelle
Une procédure de calcul bien définie qui prend en entrée un ensemble de valeurs et produit en sortie un ensemble de valeurs. C'est donc une suite d'étapes de calcul qui transforment l'entrée en sortie, et qui résout un problème de calcul bien spécifié.
Instance
Un jeu de données particulier donné en entrée du problème.
Algorithme correct
Celui qui, pour chaque instance du problème, produit la bonne sortie. La plupart de ceux vus en licence sont en plus efficaces : la mesure habituelle est la vitesse de résolution — mais la mémoire, l'énergie ou la simplicité comptent aussi dans un contexte concret.
Le problème du trispécification
Entrée : une suite de n nombres (a₁, …, aₙ) Sortie : une permutation (a′₁, …, a′ₙ) de cette suite telle que a′₁ ≤ a′₂ ≤ … ≤ a′ₙ Instance : (31, 41, 59, 26, 41, 58) Sortie : (26, 31, 41, 41, 58, 59)

Les entrées : quelles informations, sous quelle forme ?

Des nombres (entiers, réels, signés ou non), du texte (avec ses encodages ASCII, UTF-8…), des images (jpeg, png, gif, bmp, svg), du son (wav, mp3, ogg, aac), de la vidéo (MPEG-2, H.264)… et toutes ces informations sont, dans la machine, du code binaire — des 0 et des 1.

C'est exactement le sujet de la matière 03 de ce classeur, Représentation de l'information : les deux cours se rejoignent ici.

03

Le cycle de développement

Du problème au résultat, quatre étapes et trois objets intermédiaires :

  analyse        conception       codage          test
problème  →   problème    →   algorithme  →   programme   →   résultat
à résoudre    spécifique

Fil rouge du cours : donner le plus court chemin en métro entre deux stations.

1. Analyse — la phase de réflexion

le problèmeL'identifier précisément. « Plus court chemin » : en temps ou en distance ?
les donnéesPlan du réseau, temps entre deux stations, stations concernées.
les résultatsLignes à prendre, stations où changer.
les cas particuliersStations non reliées par le réseau ?
le traitementCalculer le plus court chemin — puis découper le problème en tâches simples et distinctes.

2. Conception — l'algorithme

Une suite d'opérations qui fait ressortir la logique de la résolution, proche des langages de programmation mais indépendante d'eux, et correcte quelles que soient les valeurs des données.

3. Codage — le programme

Un ou plusieurs fichiers texte d'instructions écrites dans un langage de programmation (C, Java, Fortran, Cobol, Basic…). Certains sous-programmes peuvent vivre dans des fichiers annexes : une bibliothèque de fonctions. La programmation est la traduction du langage algorithmique vers le langage de programmation.

4. Compilation et exécution

compiler puis exécuter
$ gcc cheminMetro.c -o cheminMetro   # traduction en langage machine
$ ./cheminMetro                      # l'ordinateur exécute les instructions

Un exemple, quatre langages

Problème : saluer une personne qui donne son nom. Spécification : donnée = le nom ; résultat = afficher « bonjour » suivi du nom.

L'algorithmelangage algorithmique
variables chaîne nom, salutation ; début écrire "Quel est votre nom ?" ; lire nom ; salutation ← "Bonjour " + nom ; écrire salutation ; fin
hello.c — gcc hello.c -o hello; ./hello
#include <stdio.h>
#include <string.h>
typedef char string[1024];
int main() {
    string nom, salutation;
    printf("Quel est votre nom ? ");
    scanf("%s", nom);
    sprintf(salutation, "Bonjour %s", nom);
    printf("%s\n", salutation);
}

}

05

Algorithmes et machine

Pourquoi existe-t-il autant de langages de programmation ? Parce que les performances globales d'un système dépendent autant des algorithmes que du matériel. Quatre contraintes reviennent :

  1. Une solution doit s'arrêter à un moment — pas de boucle infinie.
  2. La solution la plus simple doit être privilégiée.
  3. La ressource est toujours limitée : temps, mémoire.
  4. L'inter-opérabilité compte.
Le modèle RAM

Traditionnellement, on considère que la technologie est modélisée par une machine à accès aléatoire : les instructions s'exécutent l'une après l'autre, sans opérations simultanées ; les instructions sont arithmétiques, de transfert de données (lecture, stockage) ou de contrôle (appel de sous-routine) ; et chacune a un temps d'exécution constant.

C'est ce modèle qui rendra plus tard légitime de compter les opérations pour mesurer la complexité.

Exercice 13 — l'échange sans variable temporaire

Que fait cette séquence ?x₀, y₀ au départ
x ← x + y x = x₀ + y₀ y = y₀ y ← x - y x = x₀ + y₀ y = x₀ x ← x - y x = y₀ y = x₀

C'est un échange de x et y sans variable intermédiaire. Astucieux, mais l'échange classique reste préférable : tmp ← x ; x ← y ; y ← tmp, qui fonctionne pour tous les types alors que celui-ci exige des nombres — et déborde si les valeurs sont proches du maximum représentable, exactement le dépassement de capacité de la matière 03.

Exercice 15 — durée et division euclidienne

Secondes vers h / min / sdiv et mod
lire total ; h ← total div 3600 ; r ← total mod 3600 ; min ← r div 60 ; s ← r mod 60 ; écrire h, min, s ; // dans l'autre sens : total ← h * 3600 + min * 60 + s

C'est la même division euclidienne que dans le TD 4 de Structures fondamentales : a = bq + r avec 0 ≤ r < b.
